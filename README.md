# RoboMaster 视觉入门工程 (C++ / OpenCV)

本项目是备战 RoboMaster 视觉组的大一学习工程，旨在从零搭建一个标准化的 C++ 计算机视觉流水线。项目涵盖了从环境配置、基础图像处理、视频流实时处理到形态学优化的完整闭环。

## 🛠️ 核心功能

1. **图像预处理**：BGR 转 HSV 色彩空间，进行颜色阈值过滤（`cv::inRange`）。
2. **目标提取**：寻找色块轮廓（`cv::findContours`）并计算外接矩形（`cv::boundingRect`）。
3. **逻辑过滤**：根据目标面积（`cv::contourArea`）和长宽比（Aspect Ratio）剔除环境噪点。
4. **后处理去重**： NMS 算法（基于 IoU 交并比），剔除重叠的候选框。
5. **视频流处理**：使用 `cv::VideoCapture` 实时读取，控制窗口缩放并实现无限循环播放。
6. **形态学降噪**：利用开闭运算（`cv::morphologyEx`）填补目标空洞、消除反光噪点。

## 📅 开发日志 (Changelog)

### Day 1-3：工程环境搭建与传统视觉基础
- **环境搭建**：配置 WSL2 (Ubuntu 24.04) + VS Code + CMake + OpenCV 4.6。
- **图像处理**：掌握 `imread`、`cvtColor`（转HSV）、`inRange`（颜色掩膜）。
- **过滤逻辑**：通过 `contourArea` 实现面积过滤，通过 `boundingRect` 计算长宽比过滤。
- **算法集成**：将手搓的 **NMS（非极大值抑制）** 算法以多文件形式集成进工程，成功剔除重叠框。
- **Git进阶**：掌握了创建分支，解决 Merge 冲突，并成功在 GitHub 提交了 PR (Pull Request)。

### Day 4：视频流处理、性能监测与性能瓶颈分析
- **视频流**：使用 `VideoCapture` 替换 `imread`，通过 `while(true)` 循环实现逐帧读取处理。
- **性能监控**：使用 `getTickCount` 和 `getTickFrequency` 计算 `Read`（读图）耗时与 `Process`（处理）耗时，并实时打印在画面上。
- **核心提速**：发现高清视频处理卡顿后，使用 `cv::resize` 将画面降采样（缩小一半），FPS 从低于 100 飙升至 200 以上。
- **循环播放**：通过 `cap.set(cv::CAP_PROP_POS_FRAMES, 0);` 实现视频读取到末尾后自动倒带重播。

### Day 5：颜色切换与形态学降噪实战
- **场景挑战**：将阈值切为提取“白色”。受视频中的反光与白墙干扰，瞬间产生 **1676 个** 轮廓，导致 CPU 负担极重。
- **形态学魔法**：引入 `cv::getStructuringElement` 构建 5x5 核，利用 `morphologyEx` 的 `MORPH_OPEN`（开运算）进行降噪。
- **数据验证**：经过形态学过滤后，原始轮廓数量从 1676 暴降至 **81**，成功保住了 CPU 算力。

### Day 6：复杂场景调优与极限性能榨干
- **场景挑战**：挑战星空动态视频，提取红色流星。由于流星头部极亮、尾部偏暗，导致原本被切分成两个框。
- **调优策略**：
  1. 放宽 `ratio` 上限，适应极长的尾迹。
  2. 使用大尺寸核（如 `15x15` 或 `21x21`）进行 `MORPH_CLOSE`（闭运算），强行将碎裂的头部和尾部连通。
- **成果**：成功用**单一绿框**完整锁定流星头尾。由于轮廓数量大幅减少，算法耗时维持在 **1ms**，FPS 突破 **400**，实现了极致的性能榨干。
## 📅 Day 7：几何特征提取与二值化底层逻辑

- **业务场景**：针对 27 赛季点阵屏装甲板与 AprilTag 的识别需求，探索基于形状的提取（不再依赖颜色）。
- **核心函数与流水线**：
  1. **灰度化**：`cv::cvtColor`（BGR 转 GRAY），剥离色彩干扰，减少算力。
  2. **二值化**：`cv::threshold`（固定阈值），将灰度图化为纯黑纯白，提取亮度特征。
  3. **形态学闭运算**：`cv::morphologyEx` (MORPH_CLOSE)，填补目标内部空洞，连接断裂的边缘。
  4. **多边形拟合**：`cv::approxPolyDP`，通过计算轮廓周长，判断目标是否正好由 4 个顶点组成，以此过滤掉圆形或复杂形状的干扰。
  5. **凸包检测**：`cv::isContourConvex`，确保提取的四边形是凸多边形（排除凹进去的假轮廓）。
- **踩坑与真实数据**：
  - 在尝试识别雪景房屋时，因房屋边缘积雪/纹理导致轮廓断裂，初始提取出的四边形数量为 **0**。
  - 同时，因为树枝的缝隙偶然形成四边形，导致误检（框到了树）。
- **调试与突破**：
  - 通过放宽 `approxPolyDP` 的精度（`0.02 * peri` 改为 `0.05 * peri`），并配合形态学大核，成功提取出画面中 4 个较完整的暗色几何块。
  - 通过单独 `imshow` 二值化黑白图，直观地验证了“计算机眼中的世界”。
- **技术反思**：深刻体会到传统视觉（阈值二值化）对光照极度敏感的缺陷。光线稍变，阈值 `100` 就可能失效。这为后续向 **YOLO 深度学习**（基于纹理与特征，不惧光照变化）过渡

## 📅 Day 8：Caffe-SSD 模型部署实战与踩坑

- **任务目标**：尝试使用 OpenCV DNN 模块在 C++ 中加载预训练的 MobileNet-SSD Caffe 模型，实现对视频流中目标的检测。
- **核心流程**：
  1. 模型加载：`readNetFromCaffe` 读取 `.prototxt` 和 `.caffemodel`。
  2. 预处理：`blobFromImage` 将图像转为 300x300 的 Blob，并做归一化及减均值处理。
  3. 推理与后处理：提取置信度大于 0.2 的目标，过滤背景（类别0），并通过 `NMSBoxes` 进行去重。
- **踩坑与经验**：
  1. **网络代理问题**：国内直连下载 Caffe 模型极易断连或下载到 0 字节的假模型（通过 `ls -lh` 成功排雷）。
  2. **老模型的局限性**：MobileNet-SSD 对画面占比过大的目标（如占满屏幕的狗）存在严重的特征丢失，只能输出“瓶子”等错误类别或坐标出界的假框。
  3. **尺寸过滤**：加入了 `w < frame.cols * 0.4` 等极度严格的宽高过滤，成功清理了离谱的误检框。
- **下一步计划**：放弃老旧模型，迁移至现代 YOLOv8 的静态 ONNX 模型。

## 📅 Day 9：源码编译 OpenCV 4.10 与 YOLOv8 部署

- **核心痛点**：OpenCV 4.6 的 DNN 模块无法解析 YOLOv8 的 ONNX 模型（报 Shape 节点动态形状错误）。
- **终极解决方案（源码编译）**：
  - 放弃不完整的 deb 包，改用 `wget` 从 Gitee 镜像极速拉取完整的 `opencv-4.10.0.zip` 源码（约 95MB）。
  - 安装 GTK、FFmpeg 等全套依赖（`libgtk-3-dev` 等），解决 `imshow` 弹窗问题。
  - 使用 CMake 配置，开启 `OPENCV_GENERATE_PKGCONFIG`，设置 `OPENCV_DOWNLOAD_MIRROR_ID=gitcode` 加速依赖。
  - 执行 `make -j$(nproc)` 多线程编译源码，最后 `sudo make install` 并刷新动态链接库 `sudo ldconfig`。
- **部署 YOLOv8n**：
  - 下载 `yolov8n.onnx` 静态模型，使用 `readNetFromONNX` 成功加载。
  - 攻克现代 YOLO 的 `[1, 84, 8400]` 张量解析逻辑：遍历 8400 个预测框，寻找 80 个类别中的最大置信度，将中心点坐标转换为真实原图坐标。
  - 结合 `NMSBoxes` 去重，最终成功用鲜红的大框极其精准地套住了测试图片中的狗，见证了现代 AI 的检测能力。
